# 渲染排序与脏矩形重绘对比 Demo

大量重叠对象的渲染优化实验: z-order 排序、脏矩形局部重绘、图层缓存,
并与全量重绘做可量化的帧率对比。

技术栈: Canvas 2D + Web Worker + PerformanceObserver + IndexedDB(零依赖, 无构建步骤)。

## 运行

```bash
# Worker 需要 http 协议, 不能用 file:// 直接打开
python3 -m http.server 8080
# 打开 http://localhost:8080
```

## 逻辑测试(无需浏览器)

```bash
node test/logic_test.mjs
```

用内置软件光栅器对渲染器做像素级等价验证: z-order、脏矩形合并、
降级、内存逐出、图层切换、增量丢失自愈等 10 项用例。

## 架构

- `js/worker.js` — 对象运动模拟(位置/层级变更), 60Hz 增量推送给主线程, 与渲染解耦
- `js/renderer.js` — 核心渲染器
  - `sortByZ`: 画家算法, `(z, id)` 稳定排序
  - `mergeRects`: 相交矩形迭代合并; 超过上限(64)合并为包围盒, 控制裁剪开销
  - `LayeredRenderer`: z 轴分层的图层缓存(离屏 canvas), 层内脏矩形局部重绘,
    主画布按合并后的全局脏区裁剪合成
- `js/main.js` — 渲染循环、基准对比(全量 5s → 脏矩形 5s)、UI、自检
- `js/db.js` — IndexedDB 持久化每次基准测试结果

## 验收标准对照

| 标准 | 实现与验证 |
| --- | --- |
| z-order 排序正确 | `(z, id)` 稳定排序; 自检 + 逻辑测试双重验证 |
| 脏矩形与全量一致 | 页面内每 60 帧自动像素哈希校验; 逻辑测试像素级 buffer 对比 |
| 帧率对照可量化 | 一键 10s 对比测试, 输出平均 FPS / P95 帧耗时 / 提升百分比, 存入 IndexedDB |
| 脏矩形合并正确 | 相交合并 + 超限包围盒降级, 合并前后数量实时显示, 单测覆盖 |
| 图层缓存正确 | 对象变层时双图层失效; 缓存命中率实时显示; 等价性测试覆盖 |
| 内存可控 | 内存预算滑块, 超预算按 LRU 逐出图层缓存(退化为裁剪内直绘), 预算恢复后自动重建; Worker 增量队列背压丢弃 |
| 降级到全量重绘 | 脏区占比超阈值自动整屏合成, HUD 实时提示并计数 |

## 关键设计

- **旧位置以渲染器本地状态为准**: Worker 增量可能被背压丢弃, 渲染器用自己保存的
  上一帧状态计算旧位置脏区, 丢帧自愈、不产生残影。
- **合成前清空脏区**: 图层透明像素经 `drawImage` 不会覆盖主画布旧内容,
  局部合成前必须在裁剪区内 `clearRect`。
- **PerformanceObserver**: 观察 `render-frame` measure(帧耗时 P95)与 `longtask`(长任务计数)。
